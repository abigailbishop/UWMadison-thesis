\chapter{Data Cleaning for the Five Station Analysis \label{chap:5sa_cleaning}}

  The data taken by the Askaryan Radio Array have been analyzed a few times for neutrinos, solar flares, and to deduce properties of the ice at the South Pole. 
  When the livetime of the five ARA stations is added together, there are roughly 28 station-years of data but only 9 years have been analyzed prior to this work.
  This is partly because of how long it takes to calibrate stations; define analysis configurations for each station; prepare noise, electronics gain, and antenna models for each configuration of each station; and build a software package to analyze so much data.
  It is also time consuming to design cuts that encompass every unique detector glitch and anthropogenic background.
  ARA currently has 5 graduate students, 1 postdoctoral researcher, and a faculty member who are devoted to analyzing the full 28 station-years of ARA data. 
  We do so by isolating a randomized 10\% of our dataset, building an analysis on this 10\% sample and a collection of simulated neutrinos, then applying the analysis framework to the full 100\% data sample.

  The procedure for this analysis is shown in Figure~\ref{fig:analysis-flowchart}.
  Chapter~\ref{chap:5sa_cleaning} discusses the generation of neutrino simulation, a surface background dataset, and a thermal background dataset through a process called ``cleaning''.
  Through data cleaning we remove traces of hardware glitches, anthropogenic backgrounds, and data not suitable for analysis.
  Then, Chapter~\ref{chap:5sa_analysis} presents the Linear Discriminant Algorithm (LDA) trained to separate thermal events from neutrinos, the optimization of the LDA Cut and the Surface Cut, and the results of applying the analysis to the 100\% dataset including the analysis' sensitivity.

  This chapter begins by detailing the creation of simulated neutrino events in Section~\ref{sec:5sa_sims}. 
  These simulations will be used to ensure that analysis cuts don't remove the very events we are searching for.
  Section~\ref{sec:a2configs} details how A2 data is partitioned into livetime configurations for analysis and simulation.
  Next, the Python package used to generate analysis variables for each event is presented in Section~\ref{sec:araproc}.
  The cleaning process then begins in Section~\ref{sec:cleaning_glitches} with the removal of events not suitable for analysis (e.g. events with glitches or poor reconstructions).
  Cleaning continues in Section~\ref{sec:cleaning_anthropogenics} with the removal of science and anthropogenic backgrounds. 
  The process for generating the surface background dataset is also discussed.
  The Fast Filter used to speed up data preparation of the 100\% sample is presented next in Section~\ref{sec:fast_filter}.
  This chapter ends with the order in which all cuts from Section~\ref{sec:cleaning_glitches}, Section~\ref{sec:cleaning_anthropogenics}, and Section~\ref{sec:fast_filter} are applied to the data and the analysis efficiencies of the cleaning procedure.
  At the end of this cleaning process, we are left only with a collection of thermal-like background events from the 10\% sample and a surface background model built on the 10\% to be optimized for the analysis discussed in Chapter~\ref{chap:5sa_analysis}. 
  
\section{Simulation Setup for Data Cleaning \label{sec:5sa_sims}}

  It is important to consider how each cut translates to overall data loss and expected neutrino rejection. 
  Neutrino events are therefore simulated uniformly in log(energy) space with energies from $10^{16}$ eV to $10^{21}$ eV. 
  As presented in Section~\ref{sec:eventLists}, neutrinos are thrown in a forward simulation along trajectories that intersect with a cylinder 15~km in radius and 3~km in depth. 
  These neutrinos interact randomly within the Earth and all outgoing particles with energy greater than $E_{\text{th}} = \text{min}(10~\text{PeV}, E_{\nu}/10)$ are simulated further. 
  Muon and tau stochastic losses, tau decays, and outgoing neutrino interactions are simulated.

\section{Defining Livetime Configurations for A2\label{sec:a2configs}}

  As detector settings and hardware change, so does the behavior of triggering and readout. 
  This has serious effects on event reconstruction and analysis (e.g. if a string is masked, this significantly affects reconstruction of events), so each station's livetime is divided into what we call ``livetime configurations". 
  Cleaning is then personalized for each livetime configuration - the cuts are the same but the exact cut thresholds change between configurations.

    }
    \label{fig:cp5_smear}
  \end{figure}

  These livetime configurations are mostly based on antenna/string masking, trigger window, and the amount of waveform readout ahead of the bin that triggered the detector, called the pre-trigger readout window or the number of pre-RF blocks. 
  Each trigger block is 10~ns and the total trigger window is defined as 
  \begin{equation}
    t_{\text{trig}} = (N_{TB}+1) \times 10~\text{ns}
    \label{eq:trigwin}
  \end{equation}
  and the default trigger window is 10 blocks, 110~ns.
  The waveform readout lengths are defined as
  \begin{equation}
    t_{\text{RF}} = N_{\text{RFB}} \times 20~\text{ns}
    \label{eq:readoutwin}
  \end{equation}
  where each RF block is 20~ns.
  There is a setting for the full waveform length, \texttt{numRF0TriggerBlocks}, and for how much waveform is saved preceding the moment the trigger fired, \texttt{numRFPreTriggerBlocks}. 
  We realized during this analysis that changes to the waveform length do not strongly affect analysis. 
  Instead, we found that the pre-trigger window matters considerably especially in interferometric reconstruction.
  For example, having a pre-trigger window that was too small has meant that the impulses from calibration pulser events were being clipped at the start of some waveforms. 
  This was noticed in June 2020 on an Operations Call and the number of pre-trigger blocks was subsequently increased from 9 (180~ns) to 14 (280~ns), resolving this problem. 
  We saw the effect in analysis for A2 runs 15527-16962 when many calibration pulser event reconstructions were not reconstructing properly, due to the newly employed analysis masking of String 1. 
  This effect is shown in Figure~\ref{fig:cp5_smear}.
  As this behavior did not line up with previously established station livetime configurations, this led to a reevaluation of configurations.

\section{Using the \texttt{AraProc} Analysis Pipeline \label{sec:araproc}}

  \texttt{AraProc}\footnote{\url{https://github.com/ara-software/AraProc/tree/main}} is a python-based framework created by Marco Muzio and Brian Clark and developed by the analysis team.
  \texttt{AraProc} creates L2 data containing a suite of analysis variables for each event calculated on the metadata and waveforms in L1 ARA data.
  Preexisting metadata that we save from the L1 data includes the time of an event, the trigger type, and the detector configuration among other settings. 
  The calculated analysis variables generated by \texttt{AraProc} include the interferometrically reconstructed azimuth, elevation, and signal correlation further described in Section~\ref{sec:reco}. 
  Other analysis variables include the average signal-to-noise ratio (SNR), the SNR of the coherently summed waveform for an event, the jackknifed average root-mean-square (RMS) voltage calculated over the noise portion of the waveforms, the impulsivity, and the spark power ratio. 
  Note that in this thesis, SNR is defined as 
  \begin{equation}
    \text{SNR} = \frac{V_{\text{PTP}}}{2 V_{\text{RMS}}}
    \label{eq:snr}
  \end{equation}
  where $V_{\text{PTP}}$ is the ``peak-to-peak'' voltage of the waveform and $V_{\text{RMS}}$ is the jackknifed RMS voltage of the noise portion of the waveform.
  Some more of these analysis variables will be explained in the coming sections as they are used to employ various cuts, but all analysis variables are explained in Appendix~\ref{app:5savariables}.
  The ROOT-formatted L1 data which includes raw waveforms take up roughly 7 GB of space per run in the 100\% sample. 
  The ROOT-formatted L2 data, condensed to only analysis variables, takes up roughly 6 MB of space per run\comment{ (check that this was a 100\% run)}. 

  The \texttt{AraProc} framework can be run on computing clusters so many runs may be processed in parallel.
  It takes 2 seconds on average to process each event, most of that is due to the continuous waveform filtering discussed in Section~\ref{sec:freq_filtering}.

  \subsection{Event Reconstruction\label{sec:reco}}

    There are two methods for event reconstruction used in this analysis. 
    The first is a hit time-based algorithm called \texttt{AraVertex} which is built into ARA's data handling package \texttt{AraRoot}\footnote{\url{https://github.com/ara-software/AraRoot/tree/master}{https://github.com/ara-software/AraRoot/tree/master}}.
    For a collection of antennas (e.g. vertically polarized antennas), the first moment in each waveform with an SNR$\geq 5$ is identified and referred to as the corresponding antenna's ``hit time''. 
    Assuming that this moment corresponds to the time when a spherical wave arrives at the detector, we use the hit time for all antennas to reconstruct the azimuth, elevation, and distance to the emitted spherical wave. 
    We perform this calculation separately for vertically and horizontally polarized antennas.

    The second method used is an interferometric reconstruction also built into \texttt{AraRoot}. 
    We assume the arriving signal may arrive from elevations evenly distributed in 1 degree bins between $-89.5$ and $89.5$, from azimuths evenly distributed in 1 degree bins between $-179.5$ and $179.5$, on a sphere of a specific radius.
    For each azimuth and elevation on this sphere and for every pair of antennas $i$ and $j$, the difference in propagation time from the given azimuth and elevation between antenna $i$ and antenna $j$, $\tau$, is calculated and used to shift one antenna $j$'s waveform in time. 
    If an impulsive signal from this direction was observed by antenna $j$ and is shifted in this way, the impulse observed by both antennas should now overlap.
    Next, the cross correlation of the two waveforms is calculated:
    \begin{equation}
      C_{i,j} = \frac{SNR_i \cdot SNR_j \sum_{t=-\inf}^{\inf} ~ V_i(t) \cdot V_j(t+\tau)}{N_{\text{overlap}} \cdot RMS_i \cdot RMS_j}
      \label{eq:crosscorr}
    \end{equation}
    where $N_{\text{overlap}}$ is the number of discrete datapoints that overlap between the two antennas' waveforms and $t$ is a time stamp in the waveform~\citep{thesis_clark}.
    The total cross correlation score is the sum of cross correlations between antenna pairs. 
    The $SNR$ and $RMS$ terms in Equation~\ref{eq:crosscorr} increase the impact of high signal antenna pairs in this equation, downweighting more thermal-like antenna pairs when cross correlating powerful signals.
    After the cross correlation score has been calculated for every possible azimuth and elevation on the reconstruction sphere, the location with the highest correlation score is reported as the best solution along with the corresponding azimuth and elevation.
    2-dimensional maps of each azimuth, elevation, and associated correlation score, such as the one shown in Figure~\ref{fig:cpevent} are called ``skymaps''.
    These skymaps also plot landmarks such as
    \begin{itemize}
      \item Frequently identifed anthropogenic backgrounds such as the South Pole (SP), IceCube Lab (ICL), and vehicles on the road to SPRESSO
      \item Known radio emitters such as radio pulsers installed in the ice on IceCube strings (e.g. IC22S)
      \item ARA Station objects such as calibrtion pulsers (identified as CP\#) and downhole antennas (identified as Ch\#)
      \item The calculated elevation from which this event would have arrived if it was a plane wave
      \item The total internal reflection angle refracted to the station's average antenna depth (identified as $\theta_c$)
    \end{itemize}

  \subsection{Frequency Filtering\label{sec:freq_filtering}}
    
    \comment{Should I have a more elaborate discussion on waveform preprocessing like block offsetting and dedispersion? }
    Much of the radio wavelength contamination ARA observes is from man-made communications frequencies referred to as ``continuous waveform'' (CW) contamination. 
    If not removed, cross correlation scores are inflated across reconstruction skymaps as the CW contamination cross correlates strongly with itself, washing out the reconstruction of impulsive events. 
    A list of frequencies registered with the South Pole Stations communications team was shared with us and is available on \url{https://aradocs.wipac.wisc.edu/cgi-bin/DocDB/ShowDocument?docid=3265}{ARA DocDB\#3265}.
    The main frequencies for us are the 450~MHz walkie talkie frequencies that motivated notch filters built into ARA event readout and the $\sim 407$~MHz Radiosonde weather balloon.
    To remove this contamination in analysis, we use the SineSubtract algorithm available in \texttt{libRootFftw}\footnote{\url{https://github.com/nichol77/libRootFftwWrapper}{https://github.com/nichol77/libRootFftwWrapper}}.
    At the start of this analysis, we used the Phase Variance method described in~\citet{thesis_clark}, however we found that this did not reliably remove all CW contamination.\footnote{\comment{Was it specifically the low power/not-so-obvious contamination? Do I need to state this at all?}}

    In addition to this so called CW filtering, we also bandpass all out of band frequencies below 50~MHz and above 875~MHz.

  \subsection{Bad Run Cut \label{sec:brc}}

    ARA manages a repository documenting runs that should be removed from analysis, called the ``runlogs''\footnote{\url{https://github.com/ara-software/runlogs/tree/main}{https://github.com/ara-software/runlogs/tree/main}}.
    These so-called ``bad runs'' are removed for some of the following reasons:
    \begin{itemize}
      \item Bad detector configuration settings for trigger windows, trigger delays, channel masking, and others
      \item Operator campaigns ``sweeps'' over values for trigger windows, trigger thresholds, waveform readout parameters, etc.
      \item Calibration campaigns involving the IceCube Laboratory rooftop pulser, IceCube deep radio pulsing, pulsing in the SPICE Core hole, surface pulsing around the station, station calibration pulser attenuation sweeps and lifts
      \item Firmware or software issues (e.g. Digitizing Daughter Array (DDA) is supplied with an unusual voltage)
      \item Incomplete runs (likely due to an operator halting the run because firmware wasn't loaded)
      \item Bad readout (e.g. unusual noise modeling parameters)
    \end{itemize}
    For this analysis we created a script that identifies runs to add to the Bad Run Log based on event rates, the length of a run, and the power supplied to the digitizers as summarized in Tab.~\ref{tab:automated_brc}

    Another class of detector glitch backgrounds is a Spark Event. 
    These events occur when one of the Digitizing Daughter Arrays (DDAs) on the station's DAQ experiences a surge of current that inflates the digitized signal.
    The waveform and spectrum of a spark event is shown in Figure~\ref{fig:spark_waveform}
    As each DDA corresponds to one string, we identify these events by identifying strings with excessive RMS compared to the others.
    The \texttt{spark\_power\_ratio} analysis variable is used for this and is calculated by determining the average RMS in each string and taking the ratio of the two strings with the greatest RMS.
    We then plot a distribution of \texttt{spark\_power\_ratio}s for each station's livetime configuration, as shown in Figure~\ref{fig:spr}, and fit the upper tail to an exponential function.
    The \texttt{spark\_power\_ratio} cut is set where the integral under the exponential tail fit beyond the cut is 1. 
    The \texttt{spark\_power\_ratio} cut for each A2 configuration is shown in Table~\ref{tab:spr}.
    An additional requirement for an event to be removed by the Spark Event Cut is placed on reconstructed elevation.
    Simply using the \texttt{spark\_power\_ratio} cut removed too many neutrinos as some neutrino interactions have enough power to saturate the waveforms on one or more strings of the detector.
    We expect neutrino events to have similar reconstructions when performed with horizontally polarized antennas and with vertically polarized antennas, but we do not expect sparky thermal-like backgrounds to do the same.
    For this reason, if the reconstructed elevation using horizontally polarized antennas is more than $2.5^{\circ}$ different from the reconstruction using vertically polarized antennas and if the event has a sufficiently large \texttt{spark\_power\_ratio}, the event is removed by the Spark Event Cut.

    There are occasions where only some antennas on a string read out waveforms with more power than the rest, so the string as a whole does not have enough power to get flagged by the Spark Event Cut.
    Event 40469 from run 3733 recorded by A4 inspired this cut as the impulsive, as shown in Figure~\ref{fig:a4outlier}.
    This event is reminiscent of 3 similar events from A2 that passed all cuts in the analysis over 4 years of A2 and A3 data, presented in \citet{ara_a23} and summarized in Section~\ref{sec:analysis_a23}: Run 3439 event 19142, run 3689 event 87466, and run 6290 event 29583 which is shown in Figure~\ref{fig:ARA-A23-sparkevent}. % https://aradocs.wipac.wisc.edu/cgi-bin/DocDB/ShowDocument?docid=2032 slide 5
    
    The anomalous channel cut is designed to remove events where one channel's waveform has (1) an unusually high amount of power and (2) does not correlate well with waveforms from other antennas of the same polarization.
    For the first, we calculate the \texttt{max\_rms\_ratio} by calculating the RMS of waveforms from all channels with like-polarization, identify the max, and divide it by the average - like an antenna level \texttt{spark\_power\_ratio}.
    For the second, we calculate the \texttt{max\_rms\_corr} by calculating the RMS of the cross correlation function between pairs of like-polarization antennas then identifying the maximum.
    We generate distributions of \texttt{max\_rms\_ratio} and \texttt{max\_rms\_corr} for both vertically and horizontally polarized antennas are composed, excluding all events removed by the Bad Run Cut, N Minutes Cut, and Spark Event Cut so the distributions are mostly thermal-like.
    The tails on these four distributions are then fit to an exponential tail, the start of which is automatically adjusted to optimize the reduced $\chi^2$ of the fit.
    Next, the cut on each polarization of \texttt{max\_rms\_ratio} and \texttt{max\_rms\_corr} is established as the point beyond which the integral under the tail's fit is 1. 
    Fits to these four variables are performed for each configuration on each station and reported in Table~\ref{tab:acc}. 
    An example of the fits from A2 configuration 7 are shown in Figure~\ref{fig:acc}.

  \subsection{Low Reconstruction Confidence Cut \label{sec:lrcc}}

    The last cut designed to remove spoiled data is one that removes signal-like events that do not reconstruct well. 
    The Low Reconstruction Confidence Cut defines signal like events as those with above thermal
    \begin{itemize}
      \item \texttt{avg\_snr\_v}, the average SNR in like-polarization antennas, 
      \item \texttt{global\_max\_corr\_v}, the maximum correlation between waveforms from pairs of like-polarization antennas, and 
      \item \texttt{impSig\_v}, the significance of the hypothesis test between a linear fit to the waveform's impulsivity curve versus an error response function plus linear fit (see Appendix~\ref{app:5savariables} for more information and an example of an impulsivity curve). 
    \end{itemize}
    A poorly reconstructing event is identified as those with below thermal
    \begin{itemize} 
      \item \texttt{corr\_contrast\_v}, the correlation contrast which is calculated by building a skymap of cross correlation scores and computing
      \begin{equation}
        \texttt{corr\_contrast} = \frac{\text{max}(\texttt{corr}) - \overline{\texttt{corr}}}{\overline{\texttt{corr}}}
        \label{eq:corr_contrast}
      \end{equation}
    \end{itemize}
    An example of an event with low correlation contrast is shown in Figure~\ref{fig:lowcorrcontrast}.
    We perform fits the usual way: plotting distributions of each variable for events not removed by the Bad Run Cut, N Minutes Cut, and Spark Event Cut, then fitting the upper tail of this distribution.
    The threshold is determined as the point beyond which the integral under the fit is 1.
    Examples of fits to the four aforementioned variables are shown in Figure~\ref{fig:lrcc} and a summary of thresholds for each variable and A2 configuration are collected in Tab.~\ref{tab:lrcc}.

\section{Removing Anthropogenic and Science Backgrounds \label{sec:cleaning_anthropogenics}}

  After all erroneously digitized and poorly reconstructing events are removed, events that include backgrounds we do not want to misclassify as neutrino signals must be removed. 
  This includes untagged calibration pulser events removed by the Geometry Cut, runs with known anthropogenic backgrounds identified with our Gumble Bad Run Identification, and potential cosmic ray and other surface-related events which we cut with the Zenith Cut and the Surface Like Cut. 

  \subsection{Geometry Cut \label{sec:gc}}

    The geometry cut is programmed to catch calibration pulser (CP) events that are not tagged as calibration pulser events. 
    This occurs if the station triggers on the CP but is saved in the moment just before or after the CP is registered as ``firing'' by the data acquisition (DAQ) board. 
    This happens at a rate of 1-in-$10^{4}$ events but these impulses mimic neutrinos and must be removed. 
    As these impulsive and well correlated events reconstruct well in azimuth and elevation, we remove untagged CP events by excluding all events that reconstruct where CP events are observed.
    
    The signals from calibration pulsers are usually recorded with strong pulses, making the interferometric reconstruction of the calpulser event obvious. 
    However, due to waveform readout and the number of pulses observed, pulser signal reconstruction can shift in such a way that secondary solutions for the reconstruction have a higher correlation score the correct solution. 
    This gives rise to populations of reconstructed calibration pulser events that are called ``mirrors".

  \subsection{Contaminated Run Identification}
    
    As discussed in Section~\ref{sec:brc}, the Bad Run Cut draws directly from the Bad Run Log for the appropriate ARA station and includes runs that should be excluded from analysis due to glitches, calibration campaigns, and known anthropogenic backgrounds that cannot be cleaned systematically (for example, a geometry cut cannot remove snowmobile backgrounds that move in reconstructed azimuth and elevation). 
    There are runs during the South Pole summer season with large anthropogenic backgrounds that are not logged in the Bad Run Log and not easily removed by spatiotemporal and surface-related cuts.
    For this reason, we created a pipeline to identify runs with large non-thermal populations of high correlation events and add them to the Bad Run Log so they will be excluded from the analysis. 

    We begin by plotting the distribution of global maximum correlation for each RF event in a run.
    We then fit two gamma Gumbel curves to the histogram because they are useful for modeling distributions that uneven and have a lot of outliers. 
    The Gumbel curve is defined as % Cite Gumbel
    \begin{equation}
      f(x) = A \frac{ \beta^{\alpha} }{ \sigma ~ \Gamma(\alpha) } e^{- ( \alpha \frac{x-\mu}{\sigma} + \beta e^{({-\frac{x-\mu}{\sigma} })} ) }
      \label{eq:gumbel}
    \end{equation}
    where $A$ is a scaling factor, $\alpha=\beta$ and is initialized to 1 and are free to be fit, $\sigma$ is called the scale parameter and is initialized as the average between the lower and upper 1$\sigma$ boundaries of the curve, and $\mu$ is called the location factor and is initialized as bin where the distribution is maximal. 
    The first gamma Gumbel curve is fit to the thermal background and the second is fit to the remaining outliers. 
    Examples of the gamma Gumbel curve fits to a clean and contaminated run of A2 are shown in Figure~\ref{fig:gumbel-clean} and Figure~\ref{fig:gumbel-dirty}, respectively.
    The difference between the test statistics of the Poisson negative log-likelihoods for each dual component gamma Gumbel distribution is then calculated. 
    This $\Delta TS$ parameter characterizes the separation between populations of thermal backgrounds and outliers in correlation-space. 
    A low $\Delta TS$ implies low separation and that the run is not polluted with high correlation outliers. 
    A high $\Delta TS$ implies the opposite, that many events in the run are non-thermal outliers. 
    The distribution of $\Delta TS$ values for each run in a station's livetime configuration is plotted and used to identify the $\Delta TS$ threshold that will remove highly contaminated runs, as shown for A2 configuration 5 in Fig.~\ref{fig:deltaTS-per-config}. 
    For A2, the $\Delta TS$ is set to 1000 for all configurations.

    These variables and thresholds are determined differently for each station. 
    For A2, these thresholds are imposed on the impulsivity variable \texttt{bImp\_v}, reconstruction variables \texttt{corr\_contrast\_v} and \texttt{global\_max\_corr\_v}, signal strength variable \texttt{cs\_snr\_v}, and plane wave characterization variable \texttt{wavefront\_rms\_v}.
    Thresholds on all variables except \texttt{wavefront\_rms\_v} are determined by plotting the distribution of each variable for all RF events not removed by the Bad Run Cut, N Minutes Cut, or Spark Event Cut.
    Then, the upper edge of each distribution is fit to an exponential function.
    The threshold for each variable is the value beyond which the integral under the fitted exponential function is 1.
    The thresholds for A2 are presented in Table~\ref{tab:stc_variables}.
    For A2, an event needs only one analysis variable to exceed the thresholds in Table~\ref{tab:stc_variables} to be labeled as a ``signal-like'' event.

    Once signal-like events are identified, the time of each event is used to determine temporal clustering. 
    The largest time window, $t_w$ used to assemble spatio-temporal clusters is also different on each station.
    For A2 it is 60~s. 

    Lastly, for each signal-like event clustered in time, the events' reconstructed azimuth and elevation are used to identify clusters in space. 
    The solid angle in which events must reside to be removed via this cut scales as an inverse power law related to $\log(t_w)$, meaning a shorter $t_w$ will correspond to larger clusters and vice versa.
    \begin{equation}
      \ln(\Omega_w )= \frac{\ln(4\pi \times (180/\pi)^2)}{\ln(31536000)} \ln(t_w) + \ln((\pi/180)^2)
      \label{eq:stc_angularsize}
    \end{equation}
    where $t_w$ is at least 1 second and at most 1 year.
    Another way this equation has been explained to me is
    \begin{equation}
      \ln(\Omega_w )= \frac{\ln(\text{whole sky})}{\ln(\text{seconds in a year})} \ln(t_w) + \ln(\text{one square degree})
      \label{eq:stc_angularsize_jargon}
    \end{equation}
    which characterizes a line in $\ln-\ln$ space with a negative slope that relates $\Omega_w$ and $t_w$. 
    This relation has been defined such that a $t_w=1$~s corresponds to $\Omega_w=4\pi$~sterradian and a $t_w=1$~yr corresponds to $\Omega_w=1$~square degree. 

  \subsection{Zenith Cut and Surface-Like Cut \label{sec:zc_slc}}

    The Zenith Cut\footnote{
      Note, while traditionally referred to as the Zenith Cut, in this analysis this cut is imposed on events' reconstructed elevation.
    } is employed at the end of the cleaning pipeline to remove any remaining anthropogenic surface events, such as continuous wave contaminated events that weren't fully filtered and cosmic ray events. 
    % The cosmic ray events that ARA can observe typically result from an ultra high energy cosmic ray (UHECR) interacting in the atmosphere, causing an airshower, and potentially impacting into the ice. 
    Depending on the energy and direction the cosmic ray is traveling in, an ARA station may see radio signals from the air shower portion and/or the ice-impacting core. 
    % Cite Nicolas, maybe show photos
    The Zenith Cut is strict and is employed last so that it does not interfere with the Spatio-Temporal Cut and so other events can be more appropriately caught by other, more specialized cuts.

    There are also events that originate on or near the surface but that reconstruct at low elevations. 
    For example, an event with residual continuous wave contamination not removed by the algorithm discussed in Section~\ref{sec:freq_filtering} can appear as if it originated at a low elevation.
    We therefore design a cut called the Surface-Like Cut which is designed to remove events that are signal-like but have a high probability of originating from the surface. 
    An event is determined as signal-like using the same metrics defined in Section~\ref{sec:lrcc}.
    We also introduce a new analysis variable, \texttt{mindepth\_v}, which characterizes the highest depth an event may have come from. 
    This is used to remove events that have their maximum reconstruction correlation at a low elevation but have a high probability of originating from the surface, like the event shown in Fig.~\ref{fig:lowmindepth}.

    \begin{figure}
      \centering
      \includegraphics[
          width=0.75\textwidth,
          alt={}
      ]{sections/5sa-cleaning/images/a1r3183e65990_mindepth.pdf}
      \caption{An example of an event with a high \texttt{mindepth\_v}, meaning this event has many possible reconstructions that imply this event originated near the surface. This example is A1, run 3183, event 65990.}
      \label{fig:lowmindepth}
    \end{figure}

    To set the Zenith Cut, we model the surface backgrounds, fit the tail, and set the threshold such that the integral under the tail fit beyond this value is 0.001. 
    Our surface background dataset is built from a curated list of all events with an \texttt{avg\_snr\_v}$>4.517$ (the highest threshold in Tab.~\ref{tab:lrcc}) that are not removed by the N Minutes Cut, Spark Event Cut, Low Reconstruction Confidence Cut, Geometry Cut, and do not contain any in-ice radio pulsing campaigns (e.g. SPICE Core, IceCube pulsers, calibration pulser lifts or attenuation sweeps, etc.).
    We then begin at an elevation of $-90^{\circ}$ then remove all events that originate from below this elevation and all events with a \texttt{mindepth\_v} below the depth this elevation corresponds to. 
    We fit the remaining events with a Gaussian Kernel Density Equation (KDE) and model the low elevation tail with an exponential function. 
    If a tail cannot be fit and a threshold cannot be placed in elevation that satisfies our 0.001 event leakage requirement, the elevation is increased by $1^{\circ}$ and the process is repeated. 
    For A2, this algorithm set a Zenith Cut at an elevation of $19^{\circ}$ which led to a \texttt{mindepth\_v} threshold of 82~m for the 300~m distant reconstruction sphere and 166~m for the 42.86~m pulser reconstruction sphere. 

    As we were unblinding the analysis (Section~\ref{sec:unblinding}), we were suggested to add the determination of the Zenith Cut to the analysis optimization (Section~\ref{sec:optimization}). 
    The procedure outlined in this section is used to set a temporary Zenith Cut, but the exponential model the background distribution's tail is fit to is later passed into the optimization script to help recover analysis efficiency. 

\section{Quick Removal of Thermal-Like Events during 100\% Processing with the Fast Filter \label{sec:fast_filter}}

  As every event in a run takes 1-2 seconds to be processed and there are typically $\mathcal{O}(100,000)$ events per full 100\% file, we designed an algorithm called the Fast Filter based on two computationally efficient analysis variables that can distinguish well between thermal-like and signal-like events. 
  This Fast Filter built using a Linear Discriminant Analysis (LDA) that is trained trained with thermal-like data (i.e. the events that survived all cuts) from the 10\% sample and simulated neutrinos (also with all cuts applied) labeled for the LDA as background and signal, respectively.
  The LDA is composed of four variables: \texttt{wavefront\_rms} (a measure of how compatible observed waveforms are with an arriving plane wave) and \texttt{avg\_s2} (a measure of signal causality) for each polarization of antennas. 
  Both variables can be calculated on waveforms alone, making them more efficient than building skymaps for multiple reconstruction radii and with each polarization of antennas. 
  An example of the result of the LDA training is shown in Figure~\ref{fig:fastfilter_LDA} for A2 Configuration 7.
  We choose a Fast Filter cut such that 90\% of simulated neutrinos would be preserved.
  For A2 Configuration 7, this results in a removal of over 97\% of thermal-like events in the dataset.

  \begin{figure}
    \centering
    \includegraphics[
        width=0.75\textwidth,
        alt={}
    ]{sections/5sa-cleaning/images/a2c7_fastfilter.png}
    \caption{Results of the Fast Filter's linear discriminant analysis trained on simulated neutrino data (blue, Signal line) and thermal-like data events (red, Background line). The Fast Filter Cut for A2 configuration 7 is -0.17.}
    \label{fig:fastfilter_LDA}
  \end{figure}

  We learned, after the unblinding proposal when we profiled our L2 processing code because it was taking longer than expected to run over the 100\% sample, that the main computational bottleneck was not the generation of reconstruction skymaps as we expected, but in performing the continuous waveform removal.
  In future analyses we recommend attempting to speed up continuous waveform removal as opposed to identifying events to skip during L2 processing.

\section{Employment of Cuts and Impact on Potential Neutrino Events \label{sec:5sa_cleaningsummary}}

  Once all cuts are solidified, they are applied to data in the following order: 
  \begin{enumerate}
    \item Fast Filter (100\% sample only)
    \item Bad Run and Bad Configuration Cut
    \item First Minute Cut
    \item Spark Event Cut
    \item Anomalous Channel Cut
    \item Low Reconstruction Confidence Cut
    \item Geometry and Known Sources Cut
    \item Spatio-Temporal Cut
    \item Zenith Cut
    \item Surface-Like Cut
  \end{enumerate}

  After all of these cuts are applied, the remaining dataset only contains thermal-like data and neutrino candidates. 
  Figure~\ref{fig:snrcorr_data_nocuts} shows the distribution of events' \texttt{csw\_snr\_v} and \texttt{global\_max\_corr\_v} (signal strength and signal correlation) with no cuts applied to the data.

  Figure~\ref{fig:brj} shows that 72.6\% of data RF events are removed by the cuts and Fig.~\ref{fig:sigeff} shows 43.3\% of neutrinos survive all cuts, with the Low Reconstruction Confidence Cut, Zenith Cut, and Surface Like Cut having the freatest effect on neutrino removal.
