\chapter{Data Cleaning for the Five Station Analysis \label{chap:5sa_cleaning}}

  There have been multiple analyses conducted with ARA data to search for neutrinos, solar flares, and deduce ice properties at the South Pole. 
  When the livetime of the five ARA stations are added together, it totals approximately 28 station-years of data.
  However, only 9 of those station-years have been used in analyses prior to this work.
  This is partly because of how long it takes to calibrate stations; define analysis configurations for each station; prepare noise, electronics gain, and antenna models for each configuration of each station; and build a software package to analyse so much data.
  It is also time consuming to design cuts that encompass every unique detector glitch and anthropogenic background.
  ARA currently has 5 graduate students, 1 postdoctoral researcher, and a faculty member who are devoted to analyzing the full 28 station-years of ARA data. 
  We isolate a randomized 10\% of our dataset, build an analysis on this 10\% sample and a collection of simulated neutrino signal, and finally apply the analysis framework to the full 100\% data sample.

  Chapter~\ref{chap:5sa_cleaning} discusses the generation of neutrino simulation, a surface background dataset, and a thermal background dataset through a process called ``cleaning''.
  The signal simulation was already described in Chapter~\ref{chap:veff}. 
  Rather than simulating the thermal background, we use the experimental data to build a process to separate the thermal background from the signal.
  Through data cleaning we remove events with traces of hardware glitches, anthropogenic backgrounds, and data not suitable for analysis which leaves just a thermal data sample in the end.
  Then, Chapter~\ref{chap:5sa_analysis} presents the Linear Discriminant Algorithm (LDA) trained to separate thermal events from neutrinos, the optimization of the LDA Cut and the Surface Cut, and the results of applying the analysis to the 100\% dataset including the analysis' sensitivity.

  This chapter begins by detailing the creation of simulated neutrino events in Section~\ref{sec:5sa_sims}. 
  These simulations will be used to ensure that analysis cuts don't remove the very events we are searching for.
  Section~\ref{sec:a2configs} details how A2 data is partitioned into livetime configurations for analysis and simulation.
  Next, the Python package used to generate analysis variables for each event is presented in Section~\ref{sec:araproc}.
  The cleaning process then begins in Section~\ref{sec:cleaning_glitches} with the removal of events not suitable for analysis (e.g. events with glitches or poor reconstructions).
  Cleaning continues in Section~\ref{sec:cleaning_anthropogenics} with the removal of science and physics backgrounds (e.g. impacting cores from cosmic ray air showers). 
  The process for generating the surface background dataset is also discussed.
  The Fast Filter used to speed up data preparation of the 100\% sample is presented next in Section~\ref{sec:fast_filter}.
  This chapter ends with the order in which all cuts from Section~\ref{sec:cleaning_glitches}, Section~\ref{sec:cleaning_anthropogenics}, and Section~\ref{sec:fast_filter} are applied to the data and, finally, we determine the signal efficiencies of the cleaning procedure.
  At the end of this cleaning process, we are left only with a collection of thermal-like background events from the 10\% sample and a surface background model built on the 10\% to be optimized for the analysis discussed in Chapter~\ref{chap:5sa_analysis}. 
  
\section{Simulation Setup for Data Cleaning \label{sec:5sa_sims}}

  It is important to consider how each cut translates to overall data loss and expected neutrino rejection. 
  Neutrino events are therefore simulated uniformly in $\log(E)$ space with energies, $E$, from $10^{16}$ eV to $10^{21}$ eV. 
  In scenarios where a neutrino flux model should be assumed, distributions of simulated neutrino events are weighted appropriately.
  Neutrino propagation in the Earth is accounted for and all outgoing particles with energy greater than $E_{\text{th}} = \text{min}(10~\text{PeV}, E_{\nu}/10)$ are simulated further. 
  Muon and tau stochastic losses, tau decays, and outgoing neutrino interactions are simulated.

\section{Defining Livetime Configurations for A2\label{sec:a2configs}}

  As detector settings and hardware change, so does the behavior of triggering and readout. 
  This has significant effects on event reconstruction and analysis (e.g. if a string is masked, this significantly affects reconstruction of events), so each station's livetime is divided into what we call ``livetime configurations". 
  Cleaning is then performed separately for each livetime configuration - the cuts are the same but the exact cut thresholds change between configurations.

  These livetime configurations are mostly based on antenna/string masking, trigger window, and the amount of waveform readout ahead of the bin that triggered the detector, called the pre-trigger readout window or the number of pre-RF blocks. 
  Each trigger block is 10~ns and the total trigger window, $t_{\text{trig}}$, is defined as 
  \begin{equation}
    t_{\text{trig}} = (N_{TB}+1) \times 10~\text{ns}
    \label{eq:trigwin}
  \end{equation}
  and the default number of trigger window blocks, $N_{TB}$, is 10, leading to a default trigger window of 110~ns.
  The waveform readout lengths, $t_{\text{RF}}$, are defined as
  \begin{equation}
    t_{\text{RF}} = N_{\text{RFB}} \times 20~\text{ns}
    \label{eq:readoutwin}
  \end{equation}
  where each RF block is 20~ns and $N_{\text{RFB}}$ is the number of RF blocks.
  There is a setting for the full waveform length, \texttt{numRF0TriggerBlocks}, and for how much waveform is saved preceding the moment the trigger fired, \texttt{numRFPreTriggerBlocks}. 
  The dominant effect on reconstruction quality was found to be the pre-trigger window, whereas the waveform length does not significantly affect the analysis.
  For example, having a pre-trigger window that is too small means that the impulsive signals from calibration pulser events are clipped at the start of some waveforms which reduces the amount of information available for event reconstruction. 
  This effect on calibration pulser reconstruction is shown in Figure~\ref{fig:cp5_smear}.
  This setting was corrected in 2020 starting with run 16963 by increasing the pre-trigger window from 180~ns to 280~ns.
  As this behavior did not line up with previously established station livetime configurations, this led to a reevaluation of configurations.

\section{Using the \texttt{AraProc} Analysis Pipeline \label{sec:araproc}}

  \texttt{AraProc}\footnote{\url{https://github.com/ara-software/AraProc/tree/main}} is a Python-based framework created by Marco Muzio and Brian Clark and developed by the analysis team.
  \texttt{AraProc} creates L2 data containing a suite of analysis variables for each event calculated on the metadata and waveforms in L1 ARA data.
  Preexisting metadata that we save from the L1 data includes the time of an event, the trigger type, and the detector configuration among other settings. 
  The calculated analysis variables generated by \texttt{AraProc} include the interferometrically reconstructed azimuth, elevation, and signal correlation further described in Section~\ref{sec:reco}. 
  Other analysis variables include the root-mean-square (RMS) voltage calculated over the noise portion of the waveforms from like-polarization antennas, the average signal-to-noise ratio (SNR) of all like-polarization antennas, the SNR of the coherently summed waveform for an event, the impulsivity, and the spark power ratio. 
  The RMS is calculated as
  \begin{equation}
    \sigma = \sqrt{ \frac{1}{N} \sum_i^N V_i^2}
  \end{equation}
  where $V_i$ is the voltage recorded at one time and $N$ is the total number of data points\footnote{During data conditioning, the average value of all waveforms is asserted to be 0~V.}.
  The SNR is defined as 
  \begin{equation}
    \text{SNR} = \frac{1}{2} \big( \text{max}(V) - \text{min}(V) \big) ~/~ \sigma 
    \label{eq:snr}
  \end{equation}
  where $V$ is a series of voltage data points.
  Some more of these analysis variables will be explained in the coming sections as they are used to employ various cuts, but all analysis variables are explained in Appendix~\ref{app:5savariables}.
  The ROOT-formatted L1 data which includes raw waveforms take up roughly 7 GB of space per 3-hour run in the 100\% sample. 
  The ROOT-formatted L2 data, condensed to only analysis variables, takes up roughly 6 MB of space per run\comment{ (check that this was a 100\% run)}. 

  \subsection{Angular Event Reconstruction\label{sec:reco}}

    There are two methods for event reconstruction used in this analysis. 
    The first is a hit time-based algorithm called \texttt{AraVertex} which is built into ARA's data handling package \texttt{AraRoot}\footnote{\url{https://github.com/ara-software/AraRoot/tree/master}}.
    For a collection of antennas (e.g. vertically polarized antennas), the first instance in each waveform with an SNR$\geq 5.0$ is identified and referred to as the corresponding antenna's ``hit time''. 
    Assuming that this moment corresponds to the time when a spherical wave arrives at the detector, we use the hit time for all antennas to reconstruct the azimuth, elevation, and distance to the emitted spherical wave. 
    We perform this calculation separately for vertically and horizontally polarized antennas.

    The second method used is an interferometric reconstruction also built into \texttt{AraRoot}. 
    The signal is assumed to originate from elevations evenly distributed in 1 degree bins between $-89.5^{\circ}$ and $89.5^{\circ}$ and from azimuth angles between $-179.5^{\circ}$ and $179.5^{\circ}$ on a sphere of a specific radius.
    For each azimuth and elevation on this sphere and for every pair of antennas $i$ and $j$, the difference in propagation time from the given azimuth and elevation between antenna $i$ and antenna $j$, $\tau$, is calculated and used to shift one antenna $j$'s waveform in time. 
    If a common signal from this direction was observed by antenna $j$ and is shifted in this way, the signals observed by both antennas should now overlap.
    Next, the cross correlation between waveform $i$ and waveform $j$ is calculated:
    \begin{equation}
      C_{i,j}(\theta, \phi; R) = \frac{1}{\sigma_i ~ \sigma_j} \sum_{t=-\infty}^{\infty} ~ V_i(t) ~ V_j\big(t+\tau(\theta, \phi; R)\big)
    \end{equation}
    where $t$ is a time stamp in the waveform, and $\tau(\theta, \phi; R)$ is the time delay between antennas for a signal originating from a location ~\citep{thesis_clark}.
    The total cross correlation score is the sum of cross correlations between all pairs of like-polarization antennas
    \begin{equation}
      C = \sum_{i,j} w_{i,j} ~ C_{i,j}(\tau)
      \label{eq:crosscorr}
    \end{equation}
    where $w_{i,j}$ is a weighting term defined as 
    \begin{equation}
      w_{i,j} = \frac{ (SNR_i - 1) (SNR_j - 1)}{ \sum_{i', j'}(SNR_{i'} - 1)(SNR_{j'} - 1)}
    \end{equation}
    The $SNR$ terms in Equation~\ref{eq:crosscorr} increase the impact of high signal antenna pairs in this equation, down-weighting more thermal-like antenna pairs when cross correlating powerful signals.
    After the cross correlation score has been calculated for every possible azimuth and elevation (each with their own corresponding $\tau$) on the reconstruction sphere.
    The coordinate system used for event reconstruction is centered on the station's average antenna position.
    The location on this sphere with the highest correlation score is reported as the best solution along with the corresponding azimuth and elevation.
    2-dimensional maps of each azimuth, elevation, and associated correlation score, such as the one shown in Figure~\ref{fig:cpevent_reco} are called ``skymaps''.
    These skymaps also plot landmarks such as
    \begin{itemize}
      \item Frequently identified anthropogenic backgrounds such as the South Pole (SP), IceCube Lab (ICL), and vehicles on the road to SPRESSO
      \item Known radio emitters such as radio pulsers installed in the ice on IceCube strings (e.g. IC22S)
      \item ARA Station objects such as calibration pulsers (identified as CP\#) and downhole antennas (identified as Ch\#)
      \item The calculated elevation from which this event would have arrived if it was a plane wave
      \item The total internal reflection angle refracted to the station's average antenna depth (identified as $\theta_c$)
    \end{itemize}

  \subsection{Frequency Filtering\label{sec:freq_filtering}}
    
    % Albrecht and ali suggest "maybe" discussing dedispersion but its never mentioned again for the analysis.
    Much of the radio wavelength contamination ARA observes is from man-made communications frequencies referred to as ``continuous wave'' (CW) contamination. 
    If not removed, cross correlation scores are inflated across reconstruction skymaps as the CW contamination cross correlates strongly with itself, washing out the reconstruction of impulsive events. 
    %A list of frequencies registered with the South Pole Stations communications team was shared with us and is available on \url{https://aradocs.wipac.wisc.edu/cgi-bin/DocDB/ShowDocument?docid=3265}{ARA DocDB\#3265}.
    The main communications frequencies that affect this analysis are the 450~MHz handheld radio frequencies (that motivated notch filters built into ARA event readout) and the $\sim \! 407$~MHz Radiosonde weather balloon.
    To remove this contamination in analysis, we use the SineSubtract algorithm available in \texttt{libRootFftw}\footnote{\url{https://github.com/nichol77/libRootFftwWrapper}}.
    % At the start of this analysis, we used the Phase Variance method described in~\citep{thesis_clark}, however we found that this did not reliably remove all CW contamination.

    In addition to this so-called CW filtering, we also bandpass all out-of-band frequencies below 50~MHz and above 875~MHz.
    This analysis level bandpassing is supplemental to the bandpassing done by the data acquisition board during event readout which removes frequencies below 150~MHz and above 850~MHz, as discussed in Section~\ref{sec:ARA_design}.

  \subsection{Bad Run Cut \label{sec:brc}}

    ARA manages a repository documenting runs that should be removed from analysis, called the ``runlogs''\footnote{\url{https://github.com/ara-software/runlogs/tree/main}}.
    These so-called ``bad runs'' are removed for some of the following reasons:
    \begin{itemize}
      \item Bad detector configuration settings for trigger windows, trigger delays, channel masking, and others
      \item Operator campaigns ``sweeps'' over values for trigger windows, trigger thresholds, waveform readout parameters, etc.
      \item Calibration campaigns involving the IceCube Laboratory rooftop pulser, IceCube deep radio pulsing, pulsing in the SPICE Core hole, surface pulsing around the station, station calibration pulser attenuation sweeps and lifts
      \item Firmware or software issues (e.g. Digitizing Daughter Array (DDA) is supplied with an unusual voltage)
      \item Incomplete runs (likely due to an operator halting the run because firmware wasn't loaded)
      \item Bad readout (e.g. unusual noise modeling parameters)

    Another class of detector glitch backgrounds is a Spark Event. 
    These events occur when one of the Digitizing Daughter Arrays (DDAs) on the station's DAQ experiences a surge of current that inflates the digitized signal.
    The waveform and spectrum of a spark event is shown in Figure~\ref{fig:spark_waveform}
    As each DDA corresponds to one string, we identify these events by identifying strings with excessive RMS compared to the others.
    The \texttt{spark\_power\_ratio} analysis variable is used for this and is calculated by determining the average RMS over all antennas, $N_{\text{ant}, s}$, on each string, $s$, as
    \begin{equation}
      \langle \sigma \rangle_s = \frac{1}{N_{\text{ant}, s}} \sum_a^{N_{\text{ant}, s}} \sigma_a
    \end{equation}
    then taking the ratio of the two strings with the greatest $\langle \sigma \rangle_s $.
    We then plot a distribution of \texttt{spark\_power\_ratio}s for a given station's livetime configuration, as shown in Figure~\ref{fig:spr}, and fit the upper tail to an exponential function.
    The \texttt{spark\_power\_ratio} cut is set where 1 background event is expected beyond the cut. 
    The \texttt{spark\_power\_ratio} cut for each A2 configuration is shown in Table~\ref{tab:spr}.
    An additional requirement for an event to be removed by the Spark Event Cut is placed on reconstructed elevation.
    Simply using the \texttt{spark\_power\_ratio} cut removed too many neutrinos as some neutrino interactions have enough power to saturate the waveforms on one or more strings of the detector.
    We expect neutrino events to have similar reconstructions when performed with horizontally polarized antennas and with vertically polarized antennas, but we do not expect sparky thermal-like backgrounds to do the same.
    For this reason, if the reconstructed elevation using horizontally polarized antennas is more than $2.5^{\circ}$ different from the reconstruction using vertically polarized antennas and if the event has a sufficiently large \texttt{spark\_power\_ratio}, the event is removed by the Spark Event Cut.

    Event 40469 from run 3733 recorded by A4 inspired this cut as the impulsive, as shown in Figure~\ref{fig:a4outlier}.
    This event is reminiscent of 3 similar events from A2 that passed all cuts in the analysis over 4 years of A2 and A3 data, presented in \citep{ara_a23} and summarized in Section~\ref{sec:analysis_a23}: Run 3439 event 19142, run 3689 event 87466, and run 6290 event 29583 which is shown in Figure~\ref{fig:ARA-A23-sparkevent}. % https://aradocs.wipac.wisc.edu/cgi-bin/DocDB/ShowDocument?docid=2032 slide 5
    
    The anomalous channel cut is designed to remove events where one channel's waveform has (1) an unusually \textbf{high amount of power} and (2) \textbf{does not correlate well} with waveforms from other antennas of the same polarization using two analysis variables:
    \begin{enumerate}
      \item \texttt{max\_rms\_ratio} is computed by diving the maximum waveform RMS among like-polarization antennas by the average - like an antenna level \texttt{spark\_power\_ratio}:
      \begin{equation}
        \texttt{max\_rms\_ratio} = \frac{ \text{max}(\sigma) }{ \langle \sigma \rangle }
      \end{equation}
      \item \texttt{max\_rms\_corr} is computed by calculating the RMS of the cross correlation function between pairs of like-polarization antennas then identifying the maximum.
    \end{enumerate}
    We generate distributions of \texttt{max\_rms\_ratio} and \texttt{max\_rms\_corr}, shown in Fig.~\ref{fig:acc}, for both vertically and horizontally polarized antennas are composed, excluding all events removed by the Bad Run Cut, N Minutes Cut, and Spark Event Cut so the distributions are mostly thermal-like.
    The tails on these four distributions are then fit to an exponential tail, the start of which is automatically adjusted to optimize the reduced $\chi^2$ of the fit.
    Next, the cut on each polarization of \texttt{max\_rms\_ratio} and \texttt{max\_rms\_corr} is established as the point beyond which the integral under the tail's fit is 1. 
    Fits to these four variables are performed for each configuration on each station and reported in Table~\ref{tab:acc}.

  \subsection{Low Reconstruction Confidence Cut \label{sec:lrcc}}

    The last cut designed to remove spoiled data is one that removes signal-like events that do not reconstruct well. 
    The Low Reconstruction Confidence Cut defines signal like events as those with above thermal
    \begin{itemize}
      \item \texttt{avg\_snr\_v}, the average SNR in like-polarization antennas, 
      \item \texttt{global\_max\_corr\_v}, the maximum correlation between waveforms from pairs of like-polarization antennas, and 
      \item \texttt{impSig\_v}, the significance of the hypothesis test between a linear fit to the waveform's impulsivity curve versus an error response function plus linear fit (see Appendix~\ref{app:5savariables} for more information and an example of an impulsivity curve). 
    \end{itemize}
    A poorly reconstructing event is identified as those with thermal
    \begin{itemize} 
      \item \texttt{corr\_contrast\_v}, the correlation contrast which is calculated by building a skymap of cross correlation scores and computing
      \begin{equation}
        \texttt{corr\_contrast} = \frac{\text{max}(\texttt{corr}) - \overline{\texttt{corr}}}{\overline{\texttt{corr}}}
        \label{eq:corr_contrast}
      \end{equation}
    \end{itemize}
    An example of an event with low correlation contrast is shown in Figure~\ref{fig:lowcorrcontrast}.
    We perform fits the usual way: plotting distributions of each variable for events not removed by the Bad Run Cut, N Minutes Cut, and Spark Event Cut, then fitting the upper tail of this distribution.
    The threshold is determined as the point beyond which the integral under the fit is 1.
    Examples of fits to the four aforementioned variables are shown in Figure~\ref{fig:lrcc} and a summary of thresholds for each variable and A2 configuration are collected in Tab.~\ref{tab:lrcc}.

\section{Removing Anthropogenic and Physics Backgrounds \label{sec:cleaning_anthropogenics}}

  After all erroneously digitized and poorly reconstructing events are removed, events that include backgrounds we do not want to misclassify as neutrino signals must be removed. 
  This includes untagged calibration pulser events removed by the Geometry Cut, runs with known anthropogenic backgrounds identified with our Gumbel Bad Run Identification, and potential cosmic ray and other surface-related events which we cut with the Zenith Cut and the Surface Like Cut. 

  \subsection{Geometry Cut \label{sec:gc}}

    The geometry cut is designed to catch calibration pulser (CP) events that are not tagged as calibration pulser events, as discussed in Section~\ref{sec:triggering}. 
    This happens once in $\sim\!10^{4}$ events but these impulsive signals mimic neutrinos and must be removed. 
    As these events reconstruct well in azimuth and elevation, we remove untagged CP events by excluding all events that reconstruct where CP events are observed.
    
    The signals from calibration pulsers are usually recorded with strong pulses, making the interferometric reconstruction of the calpulser event obvious. 
    However, due to waveform readout and the number of pulses observed, pulser signal reconstruction can shift in such a way that secondary solutions for the reconstruction have a higher correlation score than the correct solution. 
    This gives rise to populations of reconstructed calibration pulser events that are called ``mirrors''.

  \subsection{Contaminated Run Identification}
    
    As discussed in Section~\ref{sec:brc}, the Bad Run Cut draws directly from the Bad Run Log for the appropriate ARA station and includes runs that should be excluded from analysis due to glitches, calibration campaigns, and known anthropogenic backgrounds that cannot be cleaned systematically (for example, a geometry cut cannot remove snowmobile backgrounds that move in reconstructed azimuth and elevation). 
    There are runs during the South Pole summer season with large anthropogenic backgrounds that are not logged in the Bad Run Log and not easily removed by spatio-temporal and surface-related cuts.
    For this reason, we created a pipeline to identify runs with large non-thermal populations of high correlation events and add them to the Bad Run Log, so they will be excluded from the analysis. 

    We begin by plotting a distribution of the global maximum correlation for each RF event in a run.
    We then use the Generalized Gumbel (GG) probability density functions (PDFs) to parameterize if there are one or two populations of events in the distribution of correlations~\citep{gumbel1, gumbel2}.
    % GG PDFs are chosen because they are useful for modeling distributions that have a lot of outliers. 
    The GG PDF is defined as
    \begin{equation}
      f(x) = A \frac{ \lambda^{\lambda} }{ \sigma ~ \Gamma(\lambda) } e^{- ( \lambda \frac{x-\mu}{\sigma} + \lambda e^{({-\frac{x-\mu}{\sigma} })} ) }
      \label{eq:gumbel}
    \end{equation}
    where $A$ is a scaling factor, we initialize the fitting of $\lambda$ to 1 (typical handling in the UHECR community), $\sigma$ is called the scale parameter and is initialized as the average between the lower and upper 1$\sigma$ boundaries of the curve, and $\mu$ is called the location factor and is initialized as bin where the distribution is maximal. 
    We fit a single GG PDF to the distribution of correlation scores for each event in a run and we also perform a fit using a function defined by the sum of two GG PDFs.
    The test statistic,  $\Delta \text{TS}$, of the Poisson negative log-likelihoods comparing the single GG and dual GG fits is then calculated.
    Examples of the GG curve fits to a clean and contaminated run of A2 are shown in Figure~\ref{fig:gumbel-clean} and Figure~\ref{fig:gumbel-dirty}, respectively. 
    Clean runs with just a thermal population are described similarly by both the single GG distribution and the dual GG function (the second contribution in the dual GG function is suppressed by the fitting algorithm) therefore the total $\Delta \text{TS}$ comparing the two distributions is small. 
    Runs contaminated with many high correlation outliers are well described by the dual component GG function with two distinct populations.
    This does not compare strongly to the single component distribution, leading to a large $\Delta \text{TS}$.
    The distribution of $\Delta \text{TS}$ values for each run in a station's livetime configuration is plotted and used to determine the $\Delta \text{TS}$ threshold that will be used to identify highly contaminated runs which should be added to the Bad Run Log, as shown for A2 configuration 5 in Fig.~\ref{fig:deltaTS-per-config}. 
    For A2, the $\Delta \text{TS}$ is set to 1000 for all configurations.

    This cut identifies events that occur in quick succession and reconstruct to the same region of the sky. 
    Any anthropogenic background that is not removed by the Bad Run Cut (e.g. single occurrence South Pole radio emissions, snowmobiles, planes) is likely to be removed by the Spatio-Temporal Cut. 
    Events are identified for removal in clusters by first finding ``signal-like'' events, then identifying time clusters of these events, then searching for spatial clusters of these events.

    Signal-like events are identified as events that exceed one of three signal-ness thresholds.
    These variables and thresholds are determined independently for each station. 
    For A2, these thresholds are imposed on the impulsivity variable \texttt{bImp\_v}, reconstruction variables \texttt{corr\_contrast\_v} and \texttt{global\_max\_corr\_v}, signal strength variable \texttt{cs\_snr\_v}, and plane wave characterization variable \texttt{wavefront\_rms\_v}.
    Thresholds on all variables except \texttt{wavefront\_rms\_v} are determined by plotting the distribution of each variable for all RF events not removed by the Bad Run Cut, N Minutes Cut, or Spark Event Cut.
    Then, the upper tail of each distribution is fit to an exponential function.
    The threshold for each variable is the value beyond which the integral under the fitted exponential function is 1.
    The thresholds for A2 are presented in Table~\ref{tab:stc_variables}.
    For A2, an event needs only one analysis variable to exceed the thresholds in Table~\ref{tab:stc_variables} to be labeled as a ``signal-like'' event.

    Once signal-like events are identified, the time of each event is used to determine temporal clustering. 
    The largest time window, $t_w$ used to assemble spatio-temporal clusters is also different on each station.
    For A2 it is 60~s. 

    Lastly, for each signal-like event clustered in time, the events' reconstructed azimuth and elevation are used to identify clusters in space. 
    The clustering region, $\Omega_w$, in which events must reside to be removed via this cut decreases in size as the time separation, $t_w$, increases.
    This relation has been defined such that a $t_w=1$~sec corresponds to $\Omega_w=4\pi$~steradian and a $t_w=1$~yr corresponds to $\Omega_w=1$~square degree:
    \begin{equation}
      \ln(\Omega_w / 1 \text{ sq deg})= \frac{\ln(4\pi / 1 \text{ sq deg})}{\ln(\text{yr}/\text{ sec})} \ln(t_w / \text{ sec}) + \ln( 1 \text{ sq deg})
      \label{eq:stc_angularsize}
    \end{equation}
    where $t_w$ is at least 1 second and at most 1 year.
    % This characterizes a line in $\ln-\ln$ space with a negative slope that relates $\Omega_w$ and $t_w$.  

  \subsection{Zenith Cut and Surface-Like Cut \label{sec:zc_slc}}

    The Zenith Cut\footnote{
      Note, while traditionally referred to as the Zenith Cut, in this analysis this cut is imposed on events' reconstructed elevation.
    } is employed at the end of the cleaning pipeline to remove any remaining anthropogenic surface events, such as cosmic ray initiated air showers. 
    % The cosmic ray events that ARA can observe typically result from an ultra high energy cosmic ray (UHECR) interacting in the atmosphere, causing an airshower, and potentially impacting into the ice. 
    Depending on the energy and direction of the cosmic ray, an ARA station may see radio signals from the air shower portion and/or the ice-impacting core. 
    % Cite Nicolas, maybe show photos
    The Zenith Cut is strict and is employed last so that it does not interfere with the Spatio-Temporal Cut and so other events can be more appropriately caught by other, more specialized cuts.

    There are also events that originate on or near the surface but that reconstruct at elevations below the surface. 
    This can occur if there are not enough antenna pairs with strongly correlated signals, giving rise to potential ``mirror'' solutions like those discussed in Section~\ref{sec:a2configs} and Section~\ref{sec:gc}.
    % For example, an event with residual continuous wave contamination not removed by the algorithm discussed in Section~\ref{sec:freq_filtering} can appear as if it originated below the angle used for the Zenith Cut.
    We therefore design a cut called the Surface-Like Cut which is designed to remove events that are signal-like but have a high probability of originating from the surface. 
    An event is determined as signal-like using the same metrics defined in Section~\ref{sec:lrcc}.
    We also introduce a new analysis variable, \texttt{mindepth\_v}, which calculates the highest depth with a correlation score at least 60\% of the maximum for the whole reconstruction. 
    This is used to remove events that have their maximum reconstruction correlation score at a low elevation but have many solutions originating from the surface, like the event shown in Fig.~\ref{fig:lowmindepth}.

    \begin{figure}
      \centering
      \includegraphics[
          width=0.75\textwidth,
          alt={}
      ]{sections/5sa-cleaning/images/a1r3183e65990_mindepth.pdf}
      \caption{
        An example of an event with a high \texttt{mindepth\_v}, meaning this event reconstructs well at elevation angles where surface events are expected. 
        Events originating from the surface will reconstruct to elevations at or above the critical angle of total internal reflection for the medium, plotted as a red dashed line and labelled $\theta_c$. 
        In this plot, we see a green circle of highly scoring reconstruction solutions that both reconstruct towards deep ice and that approach $\theta_c$. 
        Reconstruction using this algorithm therefore does not strongly distinguish if this event originates from the surface or deep ice.
        This example is A1, run 3183, event 65990.
      }
      \label{fig:lowmindepth}
    \end{figure}

    To set these surface cuts, we model the surface backgrounds, fit the tail, and identify the highest cut thresholds where the number of passing events will not exceed 0.001. 
    Our surface background dataset is built from a curated list of all events with an \texttt{avg\_snr\_v}$>4.517$ (the highest threshold in Tab.~\ref{tab:lrcc}) that are not removed by the N Minutes Cut, Spark Event Cut, Low Reconstruction Confidence Cut, Geometry Cut, and do not contain any in-ice radio pulsing campaigns (e.g. SPICE Core, IceCube pulsers, calibration pulser lifts or attenuation sweeps, etc.).
    We fit the remaining events with a Gaussian Kernel Density Estimator (KDE) and model the low elevation tail with an exponential function. 
    For A2, this algorithm set a Zenith Cut at an elevation of $19^{\circ}$ which is converted into a \texttt{mindepth\_v} threshold of 82~m for the 300~m distant reconstruction sphere and 166~m for the 42.86~m pulser reconstruction sphere. 
    The surface cuts defined here are further optimized in Section~\ref{sec:optimization} in conjunction with the final signal-background discrimination, however the preliminary value determined here is used until then.

\section{Quick Removal of Thermal-Like Events during 100\% Processing with the Fast Filter \label{sec:fast_filter}}

  As every event in a run takes 1-2 seconds to be processed and there are typically $\mathcal{O}(10^5)$ events per full 100\% file, we designed an algorithm called the Fast Filter based on two computationally efficient analysis variables that can distinguish well between thermal-like and signal-like events. 
  This Fast Filter uses a Linear Discriminant Analysis (LDA) that is trained with thermal-like data (i.e. the events that survived all cuts) from the 10\% sample and simulated neutrinos (also with all cuts applied) labeled for the LDA as background and signal, respectively.
  The LDA is composed of four variables: 
  \begin{itemize}
    \item \texttt{wavefront\_rms\_v}: A measure of how compatible waveforms observed by vertically polarized antennas are with an arriving plane wave 
    \item \texttt{wavefront\_rms\_h}: A measure of how compatible waveforms observed by horizontally polarized antennas are with an arriving plane wave 
    \item \texttt{avg\_s2\_v}: A measure of signal causality for waveforms observed by vertically polarized antennas
    \item \texttt{avg\_s2\_h}: A measure of signal causality for waveforms observed by horizontally polarized antennas
  \end{itemize}
  These variables can be calculated on waveforms alone, making them more efficient than building skymaps for multiple reconstruction radii and with each polarization of antennas\footnote{
    We learned, after the unblinding proposal when we profiled our L2 processing code because it was taking longer than expected to run over the 100\% sample, that the main computational bottleneck was not the generation of reconstruction skymaps as we expected, but in performing the continuous waveform removal.
    In future analyses we recommend attempting to speed up continuous waveform removal as opposed to identifying events to skip during L2 processing.
  }. 
  An example of the result of the LDA training is shown in Figure~\ref{fig:fastfilter_LDA} for A2 Configuration 7.
  We choose a Fast Filter cut such that 90\% of simulated neutrinos would be preserved.
  For A2 Configuration 7, this results in a removal of over 97\% of thermal-like events in the dataset.

\section{Employment of Cuts and Impact on Potential Neutrino Events \label{sec:5sa_cleaningsummary}}

  Once all cuts are solidified, they are applied to data in the following order: 
  \begin{enumerate}
    \item Fast Filter (100\% sample only)
    \item Bad Run and Bad Configuration Cut
    \item First Minute Cut
    \item Spark Event Cut
    \item Anomalous Channel Cut
    \item Low Reconstruction Confidence Cut
    \item Geometry and Known Sources Cut
    \item Spatio-Temporal Cut
    \item Zenith Cut
    \item Surface-Like Cut
  \end{enumerate}
